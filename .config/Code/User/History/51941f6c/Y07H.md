## 🚀 How to Test

### 1. **Start the Server**

```bash
cd /home/junior/Projects/task-flow/apps/server
npm start
```

### 2. **Test Email Logging**

```bash
# Test basic email
curl -X POST http://localhost:3000/api/v1/dev/test-email \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","type":"otp"}'

# Check console for formatted email output!
```

### 3. **Test Registration Flow**

```bash
# Register user
curl -X POST http://localhost:3000/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "firstName": "Test",
    "lastName": "User",
    "role": "user"
  }'

# Copy OTP from console logs
# Verify with OTP
curl -X POST http://localhost:3000/api/v1/auth/verify-otp \
  -H "Content-Type: application/json" \
  -d '{
    "otp": "123456",
    "token": "jwt-token-from-register"
  }'
```

### 4. **Test Login Flow**

```bash
# Request login OTP
curl -X POST http://localhost:3000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "test@example.com"}'

# Copy OTP from console logs
# Verify login
curl -X POST http://localhost:3000/api/v1/auth/verify-otp \
  -H "Content-Type: application/json" \
  -d '{
    "otp": "654321",
    "token": "jwt-login-token"
  }'
```

## 🛡️ Security Features

- ✅ **Signed JWTs** prevent OTP tampering

- ✅ **Type verification** prevents token reuse
- ✅ **Database cleanup** removes used tokens
- ✅ **Production safety** - no logging in production

## 📋 Migration from Magic Links

### Old Flow:

1. User requests magic link
2. Click link in email → Direct login

### New Flow:

1. User requests OTP
2. Enter 6-digit code from email → Login

### Benefits:

- ✅ Better user experience (no email client switching)
- ✅ Works on any device
- ✅ More secure (time-limited, signed)
- ✅ Better for mobile apps
- ✅ Easier to test in development
